# ตัวเลขที่ประกาศจริง ใต้แถวในปฏิทินเศรษฐกิจ

แผงรายวันบน `/market-events` แสดง **ค่าที่ประกาศจริง** ของ release นั้น กับค่าของ
เดือนก่อนหน้า พร้อมเดือนอ้างอิงของแต่ละตัว

    ตัวเลขที่ประกาศ
    ส.ค. 2569 · พันคน 159,075   ·   ก.ค. 2569 · พันคน 158,913   (+162 พันคน)
    [ ตัวเลขเบื้องต้น จะถูกแก้ภายหลัง ]
    preliminary

## 28 จาก 40 event ไม่มีตัวเลข — **ตั้งใจ ไม่ใช่พัง**

นี่คือหัวข้อที่คนจะเข้าใจผิดมากที่สุด จึงเขียนไว้ก่อน

ชั้นตัวเลขนี้อ่านจาก **BLS อย่างเดียว** และ BLS ประกาศแค่ 3 ใน 7 kind ที่ปฏิทินมี:

| kind | จำนวน event | ผู้ประกาศ | มีตัวเลขไหม |
|---|---|---|---|
| `CPI` | 4 | BLS | ✅ |
| `PPI` | 4 | BLS | ✅ |
| `NFP` | 4 | BLS | ✅ |
| `JOBLESS_CLAIMS` | 18 | DOL | ❌ ไม่มี series ใน BLS |
| `PCE` | 4 | BEA | ❌ |
| `GDP` | 3 | BEA | ❌ |
| `FOMC` | 3 | Federal Reserve | ❌ |

**12 event ที่รองรับ · 28 event ที่ไม่มีตัวเลขเลย**

และใน 12 ตัวนั้น ยังมีเงื่อนไขที่สอง: **release ที่ยังไม่เกิด ย่อมยังไม่มีตัวเลข**
ปฏิทินยาวถึงธันวาคม ส่วน BLS ประกาศถึงเดือนล่าสุดเท่านั้น ตอนที่ generate ไฟล์
ครั้งล่าสุดมีแค่ **1 แถว** ที่มีข้อมูลจริง — NFP ของ ส.ค. 2569

> **ไม่มีค่า = ไม่ render อะไรเลย** ไม่มีหัวข้อ ไม่มีขีด `—` ไม่มีแถวว่าง
> ขีดจะทำให้คนอ่านสงสัยว่าอะไรพัง ทั้งที่คำตอบจริงคือ "ยังไม่ถึงวันประกาศ"

ถ้าเปิดแผงของวันที่ยังไม่ถึงแล้วไม่เห็นตัวเลข — **นั่นคือพฤติกรรมที่ถูกต้อง**

## SA ไม่ใช่ NSA และล็อกไว้ที่เดียว

ทุก series เป็น **seasonally adjusted** เพราะแผงนี้ตอบคำถาม
"เดือนนี้เทียบเดือนก่อนเปลี่ยนแค่ไหน" ซึ่งตอบบน NSA ไม่ได้ — NSA มีการขยับตาม
ฤดูกาลปนอยู่ในตัว ส่วนต่างเดือนต่อเดือนจึงเป็นทั้งฤดูกาลและเศรษฐกิจปนกัน โดยไม่มี
ทางบอกคนอ่านว่าส่วนไหนเป็นอะไร และ SA คือตัวที่พาดหัวข่าวอ้างถึง

ต่างกันจริงเท่าไร วัดจาก BLS วันเดียวกัน:

| | SA | NSA | ต่าง |
|---|---|---|---|
| CPI ก.ค. 2026 | 332.813 | 333.918 | 1.105 จุดดัชนี |
| NFP ส.ค. 2026 | 159,075k | 158,880k | 195,000 คน |

ตารางเดียวที่เขียน series id คือ
[`src/lib/market-events/bls-series.ts`](../src/lib/market-events/bls-series.ts)
และ `bls-series.test.ts` จะแดงถ้ามีไฟล์อื่นใน `src/` หรือ `app/` เขียน id ซ้ำ

`adjustment` ถูกเขียนลง `_provenance` ของไฟล์ข้อมูลด้วย — สลับไป NSA เมื่อไร
จะเห็นเป็น diff บนไฟล์ที่ commit ไม่ใช่ตัวเลขที่ขยับเงียบ ๆ

## ⚠️ series id ยังไม่ผ่าน catalog

BLS ยืนยันว่า series หนึ่ง ๆ คืออะไรผ่าน `catalog: true` ซึ่ง v2 ให้เฉพาะ
คำขอที่มี registration key ที่ใช้งานได้ ตอนที่ generate ไฟล์นี้ คีย์ที่มีถูก BLS
ปฏิเสธทุกตัว ข้อมูลจึงถูกดึงแบบ **anonymous** — ซึ่งได้ค่าและ footnote ครบ
แต่**ไม่ได้ชื่อทางการ**

ตัวที่อันตรายที่สุดคือ `CES0000000001` เพราะ `CES0500000001` คือ
**total private** nonfarm employment ต่างกันราว **23 ล้านคน** และคืนตัวเลขที่
"ดูเข้าท่า" พอกันทั้งคู่ ไม่มีอะไรในโปรเจกต์นี้แยกมันออกจากกันได้

หนี้ก้อนนี้**มีเทสต์คุม ไม่ใช่แค่คอมเมนต์**:
`bls-series.test.ts` **แดงอยู่** ตราบใดที่ `CATALOG_VERIFIED` ยังเป็น `false`
และจะบล็อกการ push ไปเรื่อย ๆ จนกว่าจะปลด

### วิธีปลดหนี้

1. ใส่ `BLS_API_KEY` ที่ใช้งานได้ใน `.env.local`
2. `npm run probe:bls-series`
3. เทียบ `series_title` ที่ BLS คืนมา กับ `believedToBe` ใน `bls-series.ts`
4. ถ้าตรง → ตั้ง `CATALOG_VERIFIED = true` แล้วรัน `npm run backfill:event-figures`
   ใหม่ (`catalogVerified` ในไฟล์จะกลายเป็น `true` เอง)
5. ถ้า**ไม่ตรง** → แก้ id ในตาราง แล้ว generate ใหม่ ตัวเลขที่ commit ไว้ก่อนหน้า
   ต้องถือว่าใช้ไม่ได้

## ไฟล์ข้อมูลกับการ generate

`src/data/market-event-figures.json` join กับปฏิทินด้วย `eventId`

```jsonc
{
  "schemaVersion": 1,
  "_provenance": {
    "source": "BLS",
    "api": "https://api.bls.gov/publicAPI/v2/timeseries/data/",
    "access": "anonymous",        // หรือ "registered"
    "catalogVerified": false,     // ดูหัวข้อด้านบน
    "fetchedAt": "2026-09-05T...",
    "series": [{ "kind": "CPI", "seriesId": "...", "adjustment": "SA" }]
  },
  "figures": [ /* หนึ่งแถวต่อหนึ่ง event ที่ประกาศแล้ว */ ]
}
```

สร้างด้วย:

```bash
npm run backfill:event-figures
```

- **ยิง BLS ครั้งเดียว** ขอทั้ง 3 series พร้อมกัน (โควตาให้ 50 series ต่อคำขอ)
- **ไม่ fetch ตอน render** ตัวเลขของเดือนที่ผ่านไปแล้วไม่เปลี่ยน และถ้าเปลี่ยน
  แปลว่า BLS revise ซึ่งควรมาถึงในรูป diff ที่รีวิวได้ ไม่ใช่ตัวเลขที่ขยับเอง
- **join ด้วย `referencePeriod` ไม่ใช่วันประกาศ** — release วันที่ 11 ก.ย.
  ประกาศตัวเลขของ **สิงหาคม** การเดาจากวันประกาศคือกฎที่มีข้อยกเว้น ส่วน
  `referencePeriod` ถูกถอดมาจากกำหนดการของหน่วยงานตอนที่สร้างแถวนั้น
- **ไม่แตะ `at` ในไฟล์ปฏิทิน** สคริปต์ไม่อ่านและไม่เขียนฟิลด์นั้นเลย
- ถ้าคีย์ถูกปฏิเสธ จะ retry แบบ anonymous แล้วบันทึก `access: "anonymous"` —
  ไม่มีทางที่ไฟล์จะถูกเขียนราวกับผ่าน catalog แล้วทั้งที่ไม่ได้ผ่าน

## ป้าย preliminary

BLS ติด footnote มาเอง และเราแสดงทั้งสองชั้น:

| kind | footnote จาก BLS |
|---|---|
| NFP | `preliminary` |
| PPI | `Preliminary. All indexes are subject to monthly revisions up to four months after original publication.` |
| CPI | (ไม่มี — ถือว่า final) |

**ป้ายสั้น** `ตัวเลขเบื้องต้น จะถูกแก้ภายหลัง` คือสิ่งที่คนอ่านรับรู้ได้ในแวบเดียว
**ประโยคของ BLS เอง** วางไว้ใต้ป้าย เพราะ "preliminary" กับ "แก้ได้ถึง 4 เดือน"
สัญญาคนละอย่าง

คนที่จดตัวเลขวันนี้แล้วกลับมาดูช่องเดิมเดือนธันวาคมจะเจอเลขคนละตัว — แผงต้องบอก
เขาไว้ก่อนว่าจะเป็นแบบนั้น

## สิ่งที่แผงนี้ไม่พูด

ไม่มี **forecast / consensus / estimate** ที่ไหนในโปรเจกต์นี้ ดังนั้นจึงไม่มีอะไร
ให้ "เกินคาด" หรือ "ต่ำกว่าคาด"

`EVENT_FIGURE_MUST_NOT_SAY` ใน
[`banned-copy.ts`](../src/lib/presentation/banned-copy.ts) แบน 4 คำ เฉพาะฟีเจอร์นี้:

| คำ | เหตุผล |
|---|---|
| `ผิดคาด` · `ตรงคาด` | เทียบกับ forecast ที่เราไม่มี — พูดแบบนี้คือกุความคาดหวังขึ้นมาเอง |
| `มักจะ` · `เฉลี่ย` | สองเดือนคือสองเดือน การเฉลี่ยหรือเรียกว่า "ปกติ" คือบอกว่ามันเป็นตัวอย่างของปริมาณที่เราหาลักษณะไว้แล้ว ซึ่งไม่ได้ทำ |

scope แค่ฟีเจอร์นี้ เหมือน `CARD_MUST_NOT_SAY` และ `EVENT_REACTION_MUST_NOT_SAY`
— `เฉลี่ย` เป็นคำปกติบนหน้าพอร์ตที่คำนวณค่าเฉลี่ยจริง ๆ การแบนทั้งระบบคือการแบน
เลขคณิต ไม่ใช่แบนการอ้างเกินจริง
